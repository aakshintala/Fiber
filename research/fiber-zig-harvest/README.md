# fiber-zig harvest

What the archived Zig tree knows that bears on each open ticket and fog entry on [the v0.0.1 map](https://github.com/aakshintala/fiber/issues/1). Each entry says what the issue or file decided, measured or learned. The old tree's words are quoted where they differ from `CONTEXT.md`: its "Item" is Fiber's action, and its "Run" is deliberately unnamed.

The code is at `~/work/fiber-zig`. It is read-only and never copied. High and medium entries are listed; low-value issues are counted only.

# Open tickets

## The tool contract: what every tool shares ([#14](https://github.com/aakshintala/fiber/issues/14))

**Issues**

- [fiber-zig#55](https://github.com/aakshintala/fiber-zig/issues/55) Stable tool-event contract with Fiber-owned IDs. Resolved (superseded) by the "Spec: the Fiber serve event contract" (#189): Fiber-owned item ids never change so there is no provisional-to-authoritative reconciliation step at all, and a design constraint from #22 survives into the schema: tool identity is published as an opaque name string, not a versioned `ExecutorKind`/tool-kind enum. Paths: `src/core/tooling/tool_dispatch.zig`.
- [fiber-zig#138](https://github.com/aakshintala/fiber-zig/issues/138) Core reasons about tool kinds, not builtin names (open). Directional decision (from #22) that core should reason about tool capability kinds from registry metadata rather than builtin tool names; an audit found about 211 string literals naming builtin tools in core (largest: orchestrator.zig 39, permissions.zig 26, tool_admission.zig 12) and a core "ExecutorKind" enum that lists every builtin by name, with the migration only half done. Paths: `src/core/tooling/tool_dispatch.zig`, `src/core/agent/runtime/orchestrator.zig`, `permissions.zig`, `tool_admission.zig`.
- [fiber-zig#146](https://github.com/aakshintala/fiber-zig/issues/146) Fiber-owned tool-call IDs and provider-ID reconciliation. Every item (assistant message, reasoning block, tool call) gets a Fiber-minted item_id from random bytes, assigned before any line about it is emitted and never taken from a provider; the provider's own call_id rides only in the payload of the durable finished-call line for rebuilding provider history on resume, and there is no provisional/authoritative reconciliation mechanism at all (the current unreachable reconciliation code is deleted). Paths: `src/core/agent/runtime/tool_presentation.zig`, `src/gateway/agent_request_body.zig`, `src/core/agent/execution_memory.zig`.
- [fiber-zig#147](https://github.com/aakshintala/fiber-zig/issues/147) Typed tool outcomes and shell failure categories. Closed the tool-outcome shape: status is one of completed|failed|denied|cancelled; denied carries a reason including review_* auto-mode safety holds (a hold is a denial, not its own status); failed carries error{code,message} from an open set (nonzero_exit, signal, timeout, indeterminate, startup_failed, invalid_arguments, io_failure, tool_error); process{exit_code?,signal?,timed_out} is optional and keyed by presence, never by tool name (no tool-kind enum published); and long-running work becomes a Job with its own durable lifecycle rather than a pending call status. Paths: `src/core/agent/runtime/tool_contracts.zig`, `src/core/shared/types.zig`, `src/core/tooling/tool_result_errors.zig`, `src/tools/shell/shell.zig`.
- [fiber-zig#191](https://github.com/aakshintala/fiber-zig/issues/191) Tool calls on the event stream, with typed outcomes (open). Build ticket putting tool_call_requested/_started/_delta/_completed on the stream, with the fsync durability rule this ticket establishes: fsync tool_call_started BEFORE the tool runs (the one exception to "fsync a side-effect record after it happened"), because that line is what lets a resumed reader distinguish "provably never ran" from "started, fate unknown, must not be blindly re-run"; a design-session measurement on real ~1-4MB session logs found recovery_checkpoint_set snapshots are 73-85% of total log bytes (O(k^2) re-serialization of every prior tool output per snapshot), which is what makes this the slice that deletes most of the log format; later absorbed into a full session-log rewrite (#433/#434, outside this batch's range).
- [fiber-zig#434](https://github.com/aakshintala/fiber-zig/issues/434) Rewrite the session log: one append-only record, read and write (open). The execution ticket for #433 (absorbing #201 and #191 as one ~19,000-line change, most of it deletion): defines tool_call_requested/started/completed as the durable record of a tool call (resume reads requested-with-no-started as unexecuted, started-with-no-completed as uncertain and never re-run, completed as ran), a closed completion status of completed|failed|denied|cancelled with reason/error fields, and states the rule 'no line restates the content of an earlier line in the same turn' as what makes the log linear rather than quadratic. Paths: `src/core/session/session_store.zig`, `src/core/session/session_log.zig`, `src/core/session/session_codec.zig`, `src/core/session/session_event.zig`.
- [fiber-zig#442](https://github.com/aakshintala/fiber-zig/issues/442) Spec: session and context model (open). The companion spec to #433 for what the model sees: compaction is the only mechanism that shortens history (fires at a settable 50-80% window fraction, at most one per model call, keep-budget = min(in-flight turn size, 10% of window)), a position is a seq read against a leaf with 'the latest compaction' meaning latest on the path (branch/rewind itself deferred whole to #35), a provider context-overflow is terminal with no recovery attempt and gets its own FailureKind, and tool results are bounded by one reused setting (max_tool_result_bytes, default dropping to 8 KiB) applied uniformly including command output, plus a per-model-step total budget under 30% of window so parallel calls can't clear the trigger's headroom.
- [fiber-zig#22](https://github.com/aakshintala/fiber-zig/issues/22) Remove core's remaining imports of builtins. Decided: core's two remaining production imports of `builtins/` (an MCP-menu tool spec and an ask-command tool spec) were fixed through existing dependency-injection seams with a CI guard forbidding any non-test `builtins/` import under `src/core/`, while the deeper fix — core reasoning about tool capability from registry metadata instead of builtin names ("option B") — was deferred to the tool-layer epic. Paths: `src/core/app/app_mcp_menu_runtime.zig`, `src/core/cli/cli_ask.zig`.
- [fiber-zig#440](https://github.com/aakshintala/fiber-zig/issues/440) Consolidate result_store and command_replay_store (open). Found while resolving #323: result_store and command_replay_store are two independent implementations of the same idea (full bytes of an oversized tool result behind a handle) with two directories, two handle formats, two length limits and two readers, differing only in payload framing (flat text vs a tagged stdout/stderr binary frame format for interleaved replay); proposes one store, one handle scheme, one reader with the frame tagging preserved as an encoding. Paths: `src/ui/full_transcript_screen.zig`, `src/core/session/session_child_store.zig`, `src/core/session/result_store.zig`, `src/core/session/command_replay_store.zig`.

## Background jobs: one killable object ([#20](https://github.com/aakshintala/fiber/issues/20))

**Issues**

- [fiber-zig#19](https://github.com/aakshintala/fiber-zig/issues/19) No way for a human to see or stop what the agent started. Fixed: shell-session enumeration and stop already existed end-to-end through the store/registry but was unreachable because nothing constructed a `ListFilters`; added a `list` action on the shell tool and a `/background` command rendering the agent's running shell sessions with stop, in text and JSON from one snapshot. Paths: `src/tools/shell/shell.zig`, `src/core/session/native_session.zig`, `src/core/session/contracts.zig`.
- [fiber-zig#104](https://github.com/aakshintala/fiber-zig/issues/104) Shell termination: direct_command.zig has its own 800ms kill with unbounded worker joins. Real hazard distinct from the already-fixed shared path: after the 800ms SIGKILL grace period, the direct-command executor looped joining output workers with no deadline at all, so a descendant that escaped the process group and still held a pipe open could hang the tool call forever; fix requires a deterministic upper bound after which the result is reported as an indeterminate termination, never success. Paths: `src/core/execution/direct_command.zig`.
- [fiber-zig#142](https://github.com/aakshintala/fiber-zig/issues/142) Settled: native Fiber children get the async contract. Settles four subagent decisions: mid-task feedback to a running named child is allowed (plain "message" queues feedback, "instructions" still child_busy); a parent turn may return before the child is terminal, with pending/late results as session-log events not TUI-only state; routing (model/effort) is create-time only, never mutated on a live child; and effort is a first-class create-time field. Also splits "subagent" (Fiber-hosted native child) from "delegate" (#59, any other harness, no poll/wait family), and lists a long harvest of small fx v0.0.9 fixes worth taking (MCP OAuth PKCE fallback, keep a child alive after a file-lookup error, etc). Paths: `src/core/mcp/mcp_auth.zig`, `src/core/agent/execution_memory.zig`.
- [fiber-zig#144](https://github.com/aakshintala/fiber-zig/issues/144) Map: the Fiber serve event contract. Wayfinder map that sequenced and indexes the whole event-contract program: one JSONL schema shared by stdout and the log with per-event durability, "ask --json" becomes the same stream ending in a terminal run event, per-process stdout with parent relay for children, tool identity stays an opaque name (no published tool-kind enum), and pending/late subagent results are log events; superseded #55 and #56 and handed off to /to-spec as #189. Paths: `docs/events.md`.
- [fiber-zig#149](https://github.com/aakshintala/fiber-zig/issues/149) Event taxonomy and durability. Full event-kind taxonomy and durability table: log written per item as work happens (not per turn at the end); run/turn boundaries, per-type item kinds (assistant_message_*, reasoning_*, tool_call_requested/_started/_delta/_completed) with the requested-not-started vs started-not-completed distinction preserving today's resume semantics; permission_*/elicitation_* pairs for human waits; child_started plus a job family (job_started/_delta/_completed); one usage_recorded per model call; today's history_turn_committed, usage_checkpointed and the recovery/state-replacement kinds are all retired. Paths: `src/core/session/session_event.zig`.
- [fiber-zig#152](https://github.com/aakshintala/fiber-zig/issues/152) serve and ask lifecycle. Full fiber serve/ask lifecycle: run_started is first with no replay command (a catching-up client just reads the log); a prompt during a running turn is rejected busy, steer is the explicit path and is amendable via steer_amend/steer_drop until steering_applied closes the window; cancel targets the turn only, background jobs keep running; close and stdin EOF both finish the running turn gracefully then exit (EOF is not abort); an orphaned child dies via SIGPIPE with no handler needed since Fiber installs none; SIGTERM plugs in at the flush point (flush durable lines, emit run_completed 143, exit). Paths: `src/core/cli/cli_ask.zig`, `src/core/app/app_lifecycle.zig`.
- [fiber-zig#179](https://github.com/aakshintala/fiber-zig/issues/179) /background lists jobs by job_id, not session_id. Build ticket implementing #147's Job decision: renames /background's published field, output text and help from session_id/"background session" to job_id/"job", since "session" already has a defined meaning in the glossary and long-running work is its own entity (Job) distinct from an ordinary session. Paths: `src/core/app/app_commands.zig`, `src/core/output/output_contracts.zig`.
- [fiber-zig#189](https://github.com/aakshintala/fiber-zig/issues/189) Spec: the Fiber serve event contract (open). Consolidated spec assembling all eight resolved event-contract decisions (#145-152) into one document, then sliced by /to-tickets into nine build tickets (#190-196, #199-201) with a dependency graph; later amended in comments with a tree-structured-session-log finding ("a position is a seq plus the leaf it is read against"; file order is not path order, so resume returns to the stored leaf not the end of the file), three compaction event kinds (compaction_started/_completed/_abandoned) once #33/#320 defined them, and a widened assistant_message_started payload carrying per-attempt provider/model/credential authority once RecoveryCheckpoint is deleted. Paths: `docs/events.md`.
- [fiber-zig#194](https://github.com/aakshintala/fiber-zig/issues/194) Jobs report on the event stream (open). Build ticket for job_started/_delta/_completed event kinds: a call that starts long-running work always completes within its turn (no pending status) naming a job_id, and the job then has its own durable lifecycle spanning turns, including waking a later turn_started with input wakeup naming the job_ids that fired -- the concrete event shape backing T20's "one killable object".
- [fiber-zig#90](https://github.com/aakshintala/fiber-zig/issues/90) Flaky: foreground session owner loss kills the target and descendant before delayed effects. Real timing race confirmed by a second occurrence: the test asserts a 3s delayed FINISHED effect never lands after owner-release+kill, against 2s gone-within deadlines, so a scheduling stall flips the outcome; separately measured that this one Zig test file (`command_runner`) accounts for 70.8s of a 139.1s total unit-test run, almost all real wall-clock waiting on timeout/join/reap deadlines, suggesting kill-causality should be asserted via exit signal rather than wall-clock absence of an effect file. - [fiber-zig#130](https://github.com/aakshintala/fiber-zig/issues/130) Decide: scope machine-global test baselines or keep them as leak detectors. Comparative harvest of fx v0.0.9's subagent features (create-time model/effort overrides, mid-task steering, yielded/background children with late results, recovery fixes) against Fiber's shared subagent skeleton, listing what to take/remap and what to reject (bare model names, poll/wait family, live-only yielded state); superseded by #142, which resolves the open questions it raised. - [fiber-zig#193](https://github.com/aakshintala/fiber-zig/issues/193) Steering and cancel over stdin (open). Build ticket implementing steer/steer_amend/steer_drop/cancel over stdin per #152: a queued steer message can be amended or dropped until steering_applied closes the window; cancel stops the turn (model + in-flight tool call as cancelled) but leaves background jobs running, since a Job outlives its turn by definition.

## Subagents and delegates: children on one stream ([#21](https://github.com/aakshintala/fiber/issues/21))

**Issues**

- [fiber-zig#36](https://github.com/aakshintala/fiber-zig/issues/36) Epic: subagents (open). - [fiber-zig#323](https://github.com/aakshintala/fiber-zig/issues/323) Large tool results before and after a compaction. Decided Fiber builds no context-overflow recovery at all: an overflow is terminal for the request and for the leaf until a person moves it, because an in-session compaction request is by construction larger than the request the provider just rejected, and a summarisation-free 'discard, don't describe' compaction (Codex's compact_token_budget.rs) was judged unearned; a later amendment restricts the local refusal to fire only after one real provider rejection on that leaf, never on the estimator's arithmetic alone, since an unconfirmed refusal can never be falsified or corrected. - [fiber-zig#325](https://github.com/aakshintala/fiber-zig/issues/325) Manual /compact on the compactor. /compact becomes the exact same mechanism as automatic compaction (same cut rule, keep budget, in-session summariser, three log kinds, post-compaction check) plus one optional person-supplied instruction sentence recorded verbatim on compaction_completed, deleting fx's entirely separate 'keep last turn, drop everything else, no model call' forceCompaction path. - [fiber-zig#340](https://github.com/aakshintala/fiber-zig/issues/340) What rewind and fork do to a compaction. A compaction applies to the current leaf only when the compaction item is an ancestor of it (pi's rule); a rewind landing before or inside a compaction's own kept tail silently loses that compaction and falls back to the next older one on the path (re-expanding context and discarding the cached prefix); a fork inherits a compaction purely by tree geometry with nothing copied or re-derived, unlike pi's /fork which must physically copy compaction entries into a new file; a later amendment resolves where the 'current leaf' cursor itself lives once session.json is deleted (#433): for v0.0.1, since only compaction moves the leaf and it always appends, the last log line simply is the leaf, with a small per-session cursor file as the fallback once rewind/fork can move it without appending. - [fiber-zig#347](https://github.com/aakshintala/fiber-zig/issues/347) Research: agent-driven tree navigation in the pi extension ecosystem. Research into pi's community tree/context extensions found nobody has built a working 'agent descends into a subtree and returns carrying only a summary' loop -- pi deliberately withholds leaf-movement tools from the model by design, exposing them only to person-initiated commands -- and concluded that return-with-summary is not compaction with a different continuation point but has the opposite geometry.
- [fiber-zig#348](https://github.com/aakshintala/fiber-zig/issues/348) May the model move the leaf. **Issues**

- [fiber-zig#12](https://github.com/aakshintala/fiber-zig/issues/12) Saved-session discovery is slow with many sessions (open). Measured baseline: full-scan session discovery costs 1.1s warm / 6.1s cold p50 at 10,000 sessions (~0.11ms/session warm, syscall-bound, ~71% in per-session open/read/close+stat), and even the existing index read is O(N) not O(page); the resulting contract sets a flat 2ms whole-command read budget and a per-commit write budget of ≤64KB/≤1ms p50 with ≤3× degradation from 100 to 10,000 sessions, and rules out both session pruning and a 16MB/~50,000-session index-size cliff that today permanently falls back to full scan. Paths: `src/core/session/session_store.zig`, `src/core/session/session_latest_pointer.zig`, `benchmarks/startup.sh`, `benchmarks/session_list_fixture.py`.
- [fiber-zig#121](https://github.com/aakshintala/fiber-zig/issues/121) North star: Fiber as a process (open). The accepted north-star document: Fiber is one process (config dir + session log in, same log out, clean exit) serving three deployment shapes (attended/unattended worker/orchestrator) with no host-specific features; carries load-bearing measurements (an idle-to-3-day pi/Node baseline session grew to ~4.5 GiB RSS / 9.7 GiB peak footprint, up from a 2.1 GiB single-session baseline, hypothesized partly caused by `pi-stamp` creating a new `Intl.DateTimeFormat` per date render with no caching), decided that subagents run as relayed `fiber serve` subprocesses (no in-process path), that a compaction cut may land mid-turn (never between a tool call and its result) rather than only at turn boundaries, that state lives under one `FIBER_STATE_DIR`-overridable root, and records a "weight files by fork-churn plus durable-I/O touch" method that flagged `session_log.zig` (94% of Fiber's Zig code is still fx-inherited) as carrying unexamined fx persistence assumptions. Paths: `src/core/session/session_log.zig`, `src/core/session/session_store.zig`.
- [fiber-zig#132](https://github.com/aakshintala/fiber-zig/issues/132) Private state directory per Fiber process (open). Decided (2026-09-15): a single `FIBER_STATE_DIR` env var overrides the entire `~/.fiber/` root as one absolute-path prefix (relative or empty is a startup error, never a silent fallback); the rejected alternative was separate roots per area (private sessions, shared settings/credentials) because it would force the credential-deny policy, credential-store lock and backups directory to each independently know which root they belong to, and a misconfigured pair would leak across processes silently — matches pi's `PI_CODING_AGENT_DIR`, Claude Code's `CLAUDE_CONFIG_DIR`, and Codex's `CODEX_HOME` pattern of one root, one variable.
